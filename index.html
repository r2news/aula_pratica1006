Por que relacionamento é importante?

❌ Sem relacionamento

  • Dados duplicados em várias tabelas
  • Risco de erro no cadastro
  • Dificuldade para saber o que foi vendido
  • Relatórios pobres e confusos

✅ Com relacionamento

  • Cada informação fica no lugar correto
  • A venda aponta para o cliente
  • O item vendido aponta para o produto
  • Relatórios cruzam os dados com segurança

Regras práticas antes de começar

Ordem importa

Crie primeiro as tabelas independentes. Depois crie as que dependem delas.

Chave primária

A PRIMARY KEY identifica cada registro de forma única.

Chave estrangeira

A FOREIGN KEY cria o vínculo entre duas tabelas.

⚠️ Atenção: se uma tabela possui chave estrangeira, a tabela referenciada deve existir antes.

Sequência da prática

  1. Criar o banco de dados do comércio
  2. Criar as tabelas principais (cliente, categoria, produto, venda, item_venda)
  3. Inserir alguns dados de exemplo
  4. Conferir os dados cadastrados
  5. Executar consultas básicas com SELECT
  6. Fazer um JOIN simples para enxergar o relacionamento

Em cada atividade, primeiro aparece o desafio. No slide seguinte, aparece a resposta com a query pronta.

✏️ Atividade 1 - Criar o banco

Crie um banco de dados chamado comercio_fic_pronatec e selecione esse banco para uso.

  • Use o comando de criação de banco
  • Depois informe ao MySQL que você usará esse banco

✅ Resposta 1 - Criar o banco

CREATE DATABASE comercio_fic_pronatec;
USE comercio_fic_pronatec;

✏️ Atividade 2 - Tabela cliente

Crie a tabela cliente para armazenar as pessoas que compram.

  • Inclua: id, nome, CPF, telefone, email, cidade, data de cadastro
  • CPF não pode se repetir
  • Use AUTO_INCREMENT para o ID

✅ Resposta 2 - Tabela cliente

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(150) NOT NULL,
    cpf VARCHAR(14) NOT NULL UNIQUE,
    telefone VARCHAR(20),
    email VARCHAR(150),
    cidade VARCHAR(100),
    data_cadastro DATE DEFAULT (CURRENT_DATE)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

✏️ Atividade 3 - Tabela categoria

Crie a tabela categoria para classificar os produtos.

  • Inclua: id, nome_categoria, descricao
  • Exemplos: Alimentos, Bebidas, Higiene, Limpeza, Papelaria

✅ Resposta 3 - Tabela categoria

CREATE TABLE categoria (
    id_categoria INT PRIMARY KEY AUTO_INCREMENT,
    nome_categoria VARCHAR(100) NOT NULL,
    descricao VARCHAR(255)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

✏️ Atividade 4 - Tabela produto

Crie a tabela produto e relacione com categoria.

  • Inclua: id, nome, código de barras, id_categoria, preço de custo/venda, estoque
  • Use FOREIGN KEY para relacionar com categoria

✅ Resposta 4 - Tabela produto

CREATE TABLE produto (
    id_produto INT PRIMARY KEY AUTO_INCREMENT,
    nome_produto VARCHAR(150) NOT NULL,
    codigo_barras VARCHAR(30) NOT NULL UNIQUE,
    id_categoria INT NOT NULL,
    preco_custo DECIMAL(10,2) NOT NULL,
    preco_venda DECIMAL(10,2) NOT NULL,
    estoque_atual INT NOT NULL DEFAULT 0,
    CONSTRAINT fk_produto_categoria
        FOREIGN KEY (id_categoria)
        REFERENCES categoria(id_categoria)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

✏️ Atividade 5 - Tabela venda

Crie a tabela venda para registrar vendas aos clientes.

  • Inclua: id, id_cliente, data, valor_total, forma_venda, status
  • Relacione com a tabela cliente via FOREIGN KEY

✅ Resposta 5 - Tabela venda

CREATE TABLE venda (
    id_venda INT PRIMARY KEY AUTO_INCREMENT,
    id_cliente INT NOT NULL,
    data_venda DATE DEFAULT (CURRENT_DATE),
    valor_total DECIMAL(10,2) NOT NULL,
    forma_venda VARCHAR(50) NOT NULL,
    status_venda VARCHAR(30) DEFAULT 'Finalizada',
    CONSTRAINT fk_venda_cliente
        FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

✏️ Atividade 6 - Tabela item_venda

Crie a tabela item_venda para detalhar produtos de cada venda.

  • Inclua: id, id_venda, id_produto, quantidade, valor_unitário, desconto, subtotal
  • Relacione com venda e produto

✅ Resposta 6 - Tabela item_venda

CREATE TABLE item_venda (
    id_item_venda INT PRIMARY KEY AUTO_INCREMENT,
    id_venda INT NOT NULL,
    id_produto INT NOT NULL,
    quantidade INT NOT NULL,
    valor_unitario DECIMAL(10,2) NOT NULL,
    desconto DECIMAL(10,2) DEFAULT 0.00,
    subtotal DECIMAL(10,2) NOT NULL,
    CONSTRAINT fk_item_venda_venda
        FOREIGN KEY (id_venda)
        REFERENCES venda(id_venda),
    CONSTRAINT fk_item_venda_produto
        FOREIGN KEY (id_produto)
        REFERENCES produto(id_produto)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

✏️ Atividade - Consultas básicas

Próximos passos

Vamos fazer consultas para extrair informações dos dados inseridos:

  • Listar todos os clientes
  • Filtrar clientes por cidade
  • Contar quantos clientes existem
  • Somar total das vendas
  • Listar produtos com seus preços
  • Fazer JOINs entre tabelas

SELECT - Listar clientes

Liste todos os clientes da tabela.

SELECT *
FROM cliente;

💡 O * significa "todas as colunas". Para trazer apenas algumas colunas, liste os nomes delas.

SELECT - Colunas específicas

Liste nome, preço de venda e estoque dos produtos.

SELECT 
    nome_produto,
    preco_venda,
    estoque_atual
FROM produto;

WHERE - Filtrar por cidade

Liste clientes que moram em Ibirité.

SELECT 
    nome,
    telefone,
    cidade
FROM cliente
WHERE cidade = 'Ibirité';

WHERE - Filtrar por preço

Liste produtos com preço de venda ≥ R$ 10,00.

SELECT 
    nome_produto,
    preco_venda
FROM produto
WHERE preco_venda >= 10.00;

ORDER BY - Ordenar resultados

Liste produtos do maior para o menor preço.

SELECT 
    nome_produto,
    preco_venda
FROM produto
ORDER BY preco_venda DESC;

💡 DESC = decrescente (maior para menor). ASC = ascendente (menor para maior).

COUNT - Contar registros

Quantos clientes estão cadastrados?

SELECT COUNT(*) AS total_clientes
FROM cliente;

💡 AS renomeia a coluna no resultado. COUNT(*) conta todas as linhas.

SUM - Somar valores

Qual é o faturamento total de todas as vendas?

SELECT SUM(valor_total) AS total_vendido
FROM venda;

💡 SUM() soma valores numéricos. Muito usado em relatórios financeiros.

GROUP BY - Agrupar dados

Quantos clientes existem em cada cidade?

SELECT 
    cidade,
    COUNT(*) AS quantidade_clientes
FROM cliente
GROUP BY cidade
ORDER BY quantidade_clientes DESC;

💡 GROUP BY agrupa registros pela cidade. COUNT conta quantos há em cada grupo.

JOIN - Produto com Categoria

Liste produtos mostrando a categoria de cada um.

SELECT 
    p.nome_produto AS `Produto`,
    p.preco_venda AS `Preço`,
    c.nome_categoria AS `Categoria`
FROM produto AS p
INNER JOIN categoria AS c
    ON p.id_categoria = c.id_categoria
ORDER BY c.nome_categoria;

💡 O ON (p.id_categoria = c.id_categoria) é a "cola" que conecta as tabelas.

JOIN - Venda com Cliente

Liste vendas mostrando o nome do cliente em cada venda.

SELECT 
    v.id_venda AS `Venda`,
    c.nome AS `Cliente`,
    v.data_venda AS `Data`,
    v.valor_total AS `Total`
FROM venda AS v
INNER JOIN cliente AS c
    ON v.id_cliente = c.id_cliente
ORDER BY v.data_venda;

JOIN Completo - Vendas com Detalhes

Liste cliente, venda, produto, quantidade e subtotal de cada item.

SELECT 
    c.nome AS `Cliente`,
    v.id_venda AS `Venda`,
    p.nome_produto AS `Produto`,
    iv.quantidade AS `Qtd`,
    iv.subtotal AS `Subtotal`
FROM venda AS v
INNER JOIN cliente AS c
    ON v.id_cliente = c.id_cliente
INNER JOIN item_venda AS iv
    ON v.id_venda = iv.id_venda
INNER JOIN produto AS p
    ON iv.id_produto = p.id_produto
ORDER BY c.nome, v.id_venda;
