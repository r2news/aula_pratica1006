Por que relacionamento entre tabelas é tão importante?

Sem relacionamento

  • Dados duplicados em várias tabelas.
  • Maior risco de erro no cadastro.
  • Dificuldade para saber o que foi vendido.
  • Relatórios pobres e confusos.

Com relacionamento

  • Cada informação fica no lugar correto.
  • A venda aponta para o cliente.
  • O item vendido aponta para o produto.
  • O relatório cruza os dados com segurança.

Em banco de dados relacional, a pergunta principal não é apenas “quais dados eu tenho?”, mas também “como esses dados se conectam?”

Regras práticas antes de começar

Ordem importa

Crie primeiro as tabelas independentes. Depois crie as tabelas que dependem delas.

Chave primária

A PRIMARY KEY identifica cada registro de forma única.

Chave estrangeira

A FOREIGN KEY cria o vínculo entre duas tabelas.

Atenção: se uma tabela possui chave estrangeira, a tabela referenciada precisa existir antes.

Sequência da prática

  1. Criar o banco de dados do comércio.
  2. Criar as tabelas principais.
  3. Inserir alguns dados de exemplo.
  4. Conferir os dados cadastrados.
  5. Executar consultas básicas.
  6. Fazer um JOIN simples para enxergar o relacionamento.

Atividade 1 - Criar o banco de dados

Crie um banco de dados chamado comercio_fic_pronatec e selecione esse banco para uso.

Atividade 2 - Criar a tabela de clientes

Crie a tabela cliente para armazenar os dados das pessoas que compram no comércio.

  • Inclua código do cliente como chave primária.
  • Inclua nome, CPF, telefone, e-mail, cidade e data de cadastro.
  • O CPF não pode se repetir.

Resposta 2 - Tabela cliente

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(150) NOT NULL,
    cpf VARCHAR(14) NOT NULL UNIQUE,
    telefone VARCHAR(20),
    email VARCHAR(150),
    cidade VARCHAR(100),
    data_cadastro DATE DEFAULT (CURRENT_DATE)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Atividade 3 - Criar a tabela de fornecedores

Crie a tabela fornecedor para guardar os dados das empresas que fornecem produtos ao comércio.

  • Inclua código do fornecedor como chave primária.
  • Inclua razão social, CNPJ, telefone, e-mail, cidade e data de cadastro.
  • O CNPJ não pode se repetir.

Resposta 3 - Tabela fornecedor

CREATE TABLE fornecedor (
    id_fornecedor INT PRIMARY KEY AUTO_INCREMENT,
    razao_social VARCHAR(150) NOT NULL,
    cnpj VARCHAR(18) NOT NULL UNIQUE,
    telefone VARCHAR(20),
    email VARCHAR(150),
    cidade VARCHAR(100),
    data_cadastro DATE DEFAULT (CURRENT_DATE)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Atividade 4 - Criar a tabela de categorias

Crie a tabela categoria para classificar os produtos vendidos no comércio.

  • Inclua código da categoria como chave primária.
  • Inclua nome da categoria e descrição.

Resposta 4 - Tabela categoria

CREATE TABLE categoria (
    id_categoria INT PRIMARY KEY AUTO_INCREMENT,
    nome_categoria VARCHAR(100) NOT NULL,
    descricao VARCHAR(255)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Atividade 5 - Criar a tabela de produtos

Crie a tabela produto e relacione cada produto com uma categoria.

  • Inclua código do produto como chave primária.
  • Inclua nome, código de barras, preço de custo, preço de venda, estoque e status.
  • Use chave estrangeira para relacionar produto com categoria.

Resposta 5 - Tabela produto

CREATE TABLE produto (
    id_produto INT PRIMARY KEY AUTO_INCREMENT,
    nome_produto VARCHAR(150) NOT NULL,
    codigo_barras VARCHAR(30) NOT NULL UNIQUE,
    id_categoria INT NOT NULL,
    preco_custo DECIMAL(10,2) NOT NULL,
    preco_venda DECIMAL(10,2) NOT NULL,
    estoque_atual INT NOT NULL DEFAULT 0,
    estoque_minimo INT NOT NULL DEFAULT 0,
    ativo CHAR(1) DEFAULT 'S',

    CONSTRAINT fk_produto_categoria
        FOREIGN KEY (id_categoria)
        REFERENCES categoria(id_categoria)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Atividade 6 - Criar a tabela de vendas

Crie a tabela venda para registrar as vendas realizadas para os clientes.

  • Inclua código da venda como chave primária.
  • Inclua cliente, data da venda, valor total, forma da venda e status.
  • Use chave estrangeira para relacionar venda com cliente.

Resposta 6 - Tabela venda

CREATE TABLE venda (
    id_venda INT PRIMARY KEY AUTO_INCREMENT,
    id_cliente INT NOT NULL,
    data_venda DATE DEFAULT (CURRENT_DATE),
    valor_total DECIMAL(10,2) NOT NULL,
    forma_venda VARCHAR(50) NOT NULL,
    status_venda VARCHAR(30) DEFAULT 'Finalizada',

    CONSTRAINT fk_venda_cliente
        FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Atividade 7 - Criar a tabela de itens da venda

Crie a tabela item_venda para detalhar quais produtos foram vendidos em cada venda.

  • Relacione o item com a venda.
  • Relacione o item com o produto.
  • Inclua quantidade, valor unitário, desconto e subtotal.

Resposta 7 - Tabela item_venda

CREATE TABLE item_venda (
    id_item_venda INT PRIMARY KEY AUTO_INCREMENT,
    id_venda INT NOT NULL,
    id_produto INT NOT NULL,
    quantidade INT NOT NULL,
    valor_unitario DECIMAL(10,2) NOT NULL,
    desconto DECIMAL(10,2) DEFAULT 0.00,
    subtotal DECIMAL(10,2) NOT NULL,

    CONSTRAINT fk_item_venda_venda
        FOREIGN KEY (id_venda)
        REFERENCES venda(id_venda),

    CONSTRAINT fk_item_venda_produto
        FOREIGN KEY (id_produto)
        REFERENCES produto(id_produto)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Atividade 17 - Ordenar produtos pelo preço

Liste os produtos do maior para o menor preço de venda.

O que o aluno precisa pensar

  • Qual tabela guarda os produtos?
  • Quais colunas devem aparecer no resultado?
  • Qual coluna será usada para organizar a lista?
  • A ordem será crescente ou decrescente?

Dica didática

ORDER BY organiza o resultado. DESC mostra do maior para o menor. Neste caso, o preço mais alto deve aparecer primeiro.

Resposta 17 - Ordenar produtos pelo preço

SELECT 
    nome_produto,
    preco_venda
FROM produto
ORDER BY preco_venda DESC;

Entenda o comando

  • SELECT escolhe as colunas que serão exibidas.
  • FROM produto informa de qual tabela os dados serão buscados.
  • ORDER BY preco_venda ordena pelo preço de venda.
  • DESC significa ordem decrescente: maior para menor.

Atividade 18 - Contar clientes cadastrados

Faça uma consulta para contar quantos clientes existem cadastrados.

O que deve ser respondido

A consulta não precisa mostrar o nome de cada cliente. Ela deve retornar apenas um número: o total de registros cadastrados na tabela de clientes.

Dica didática

A função COUNT(*) conta linhas. Se existem 6 clientes na tabela, o resultado será 6.

Resposta 18 - Contar clientes

SELECT COUNT(*) AS total_clientes
FROM cliente;

Entenda o comando

  • COUNT(*) conta todas as linhas encontradas.
  • AS total_clientes dá um nome amigável para a coluna do resultado.
  • FROM cliente indica que a contagem será feita na tabela cliente.

Atividade 19 - Somar o total das vendas

Some o valor total de todas as vendas cadastradas.

O que deve ser respondido

A consulta deve gerar um relatório simples de faturamento, somando todos os valores registrados na coluna valor_total.

Dica didática

A função SUM() soma valores numéricos. Ela é muito usada em relatórios de vendas, compras, estoque e financeiro.

Resposta 19 - Somar vendas

SELECT SUM(valor_total) AS total_vendido
FROM venda;

Entenda o comando

  • SUM(valor_total) soma todos os valores da coluna valor_total.
  • AS total_vendido define o nome da coluna calculada.
  • FROM venda mostra que a soma será feita com base nas vendas.

Atividade 20 - Agrupar clientes por cidade

Conte quantos clientes existem em cada cidade.

O que significa agrupar?

Agrupar é juntar registros que possuem a mesma informação. Aqui, todos os clientes de Ibirité ficam em um grupo, os de Betim em outro, e assim por diante.

Dica didática

Quando usamos GROUP BY cidade, o MySQL forma grupos por cidade. Depois, o COUNT(*) conta quantos clientes existem em cada grupo.

Resposta 20 - Clientes por cidade

SELECT 
    cidade,
    COUNT(*) AS quantidade_clientes
FROM cliente
GROUP BY cidade
ORDER BY quantidade_clientes DESC;

Entenda o comando

  • cidade aparece no resultado porque será o campo de agrupamento.
  • COUNT(*) conta quantos clientes existem em cada cidade.
  • GROUP BY cidade separa os registros por cidade.
  • ORDER BY ... DESC mostra primeiro a cidade com mais clientes.

Atividade 21 - JOIN entre produto e categoria

Liste os produtos mostrando também o nome da categoria de cada um.

Por que precisa de JOIN?

Na tabela produto, não guardamos o nome da categoria. Guardamos apenas o código id_categoria. O nome da categoria está em outra tabela: categoria.

Raciocínio da consulta

  • Pegar os dados do produto.
  • Ir até a tabela categoria.
  • Ligar as duas pelo campo id_categoria.
  • Mostrar o produto junto com o nome da categoria.

Resposta 21 - Produto com categoria

SELECT 
    p.nome_produto AS `Produto`,
    p.preco_venda AS `Preço de Venda`,
    c.nome_categoria AS `Categoria`
FROM produto AS p
INNER JOIN categoria AS c
    ON p.id_categoria = c.id_categoria
ORDER BY c.nome_categoria, p.nome_produto;

Entenda o JOIN

  • produto AS p: apelido curto para a tabela produto.
  • categoria AS c: apelido curto para a tabela categoria.
  • INNER JOIN une registros que possuem relação nas duas tabelas.
  • ON p.id_categoria = c.id_categoria é a condição da ligação.
  • Sem o ON, o banco não sabe como conectar produto e categoria.

Atividade 22 - JOIN entre venda e cliente

Liste as vendas mostrando o nome do cliente, a data da venda e o valor total.

Por que precisa de JOIN?

A tabela venda guarda o código do cliente em id_cliente, mas o nome do cliente está na tabela cliente.

Raciocínio da consulta

  • A venda informa que alguém comprou.
  • O campo id_cliente informa quem comprou.
  • O JOIN busca o nome desse cliente na tabela cliente.
  • O resultado fica mais legível para o usuário.

Resposta 22 - Venda com cliente

SELECT 
    v.id_venda AS `Código da Venda`,
    c.nome AS `Cliente`,
    v.data_venda AS `Data da Venda`,
    v.valor_total AS `Valor Total`
FROM venda AS v
INNER JOIN cliente AS c
    ON v.id_cliente = c.id_cliente
ORDER BY v.data_venda, c.nome;

Entenda o JOIN

  • FROM venda AS v: a consulta começa pela tabela venda.
  • INNER JOIN cliente AS c: adiciona a tabela cliente à consulta.
  • ON v.id_cliente = c.id_cliente: liga cada venda ao seu cliente.
  • O resultado mostra dados da venda e dados do cliente na mesma tela.

Atividade 23 - JOIN completo de vendas

Liste cliente, venda, produto, quantidade e subtotal de cada item vendido.

O caminho dos dados

Uma venda não possui diretamente o nome dos produtos. Primeiro ligamos venda com cliente, depois venda com item_venda, e por fim item_venda com produto.

Mapa mental do JOIN

  • venda → registra a venda.
  • cliente → informa quem comprou.
  • item_venda → informa quais itens foram vendidos.
  • produto → informa o nome do produto.

Resposta 23 - Consulta completa de vendas

SELECT 
    c.nome AS `Cliente`,
    v.id_venda AS `Código da Venda`,
    v.data_venda AS `Data da Venda`,
    p.nome_produto AS `Produto`,
    iv.quantidade AS `Quantidade`,
    iv.valor_unitario AS `Valor Unitário`,
    iv.subtotal AS `Subtotal`
FROM venda AS v
INNER JOIN cliente AS c
    ON v.id_cliente = c.id_cliente
INNER JOIN item_venda AS iv
    ON v.id_venda = iv.id_venda
INNER JOIN produto AS p
    ON iv.id_produto = p.id_produto
ORDER BY c.nome, v.id_venda, p.nome_produto;

Entenda o caminho

  • venda → cliente: descobre quem fez a compra.
  • venda → item_venda: descobre quais itens pertencem à venda.
  • item_venda → produto: descobre o nome do produto vendido.
  • SELECT escolhe o que será mostrado no relatório final.
  • ORDER BY organiza por cliente, venda e produto.
